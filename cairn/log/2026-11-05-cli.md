# A CLI waiting until a wall-clock time

The suspend checks left on macOS and Windows are the user's, by hand, on machines without a Rust toolchain, and examples/at.rs needs cargo. Asked by the user: a simple CLI to make those checks easier, the `sleep` until a time the bootstrap left for later.

What landed (e82f2bc):

- The `ceichas` binary, src/main.rs, behind the default-off `cli` feature through `required-features`, std only. It waits until an RFC 3339 datetime with `Z` or an offset, `+` and a duration in `s`, `m`, `h` and `d`, or a UNIX time, then exits 0; an error prints one line on stdout and exits 1. `--backend` names the timer, `--verbose` prints the target, then the lateness and the wall and monotonic times elapsed. No command run, no signal handler, no local time zone.
- Unit tests for the RFC 3339 parser (offsets, fractions, leap years, a leap second, rejected forms), the duration parser and the UTC formatter round trip.
- The Binaries workflow, uploading the binary for x86_64-unknown-linux-gnu, aarch64-apple-darwin, x86_64-apple-darwin and x86_64-pc-windows-msvc as workflow artifacts; the Tests workflow on `--all-features`.

Checked: locally fmt, clippy for the host and the Windows, macOS and Android targets, the unit tests, and runs on `timerfd` and `polling` (1 ms and 0 ms late over 2 to 3 s waits); in CI on e82f2bc, every Tests job, Audit, and the four Binaries builds.

Left: the user's hand checks on macOS and Windows with the binaries, suspend included, to record in the timer check table.

Capabilities moved: cli (new).
